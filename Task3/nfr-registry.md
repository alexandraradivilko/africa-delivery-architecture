# Реестр нефункциональных требований

**Область:** ограниченный MVP, Нигерия и Кения, архитектура [ADR-001](../Task2/adr-001-architecture-style.md). Все новые числовые цели — предложения архитектора на основе драйверов, а не дословные требования источников. Владелец приёмки — CTO; продуктовые SLO/SLA утверждает CEO, бюджет — CFO. Проверка доступности проводится отдельно по каждой стране и платёжному провайдеру; хорошие показатели одного сегмента не компенсируют отказ другого.

## Соответствие Cloud Native

Определение [CNCF](https://github.com/cncf/toc/blob/main/DEFINITION.md) описывает повторяемое программное управление, устойчивость и наблюдаемость; это не подтверждение сертификации нашего решения. Словосочетание «CNCF-certified» из письма CTO требует уточнить конкретную программу и объект оценки. До этого фиксируем проверяемые свойства и отдельно соответствие его приложению.

| Пункты приложения артефакта 5 | Реализация MVP / статус |
|---|---|
| CN.RPL.01 | Контейнеры — да. Kubernetes в ADR-001 отложен: **отклонение, необходимо решение CTO** |
| CN.RPL.03 | Лимиты CPU/RAM задаются декларативно runtime; буквальные Kubernetes requests/limits отсутствуют — **частичное соответствие** |
| CN.SEL.01, CN.FTL.02 | Реплики, readiness/liveness/startup-логика; liveness не зависит от доступности платёжного партнёра. Проверить NFR-08/12 |
| CN.LCP.03 | Backend и worker управляются отдельно; модули внутри backend — нет. **Ограниченная применимость**, границы компонентов должен подтвердить CTO |
| CN.LCP.05 | Внешние взаимодействия через API; между модулями — публичные интерфейсы, прямые изменения чужих таблиц запрещены |
| CN.MSV.01 | Managed допускается по проверенным цене, НФТ и резидентности; исключения для недоступных локальных услуг документируются |
| CN.ADL.01/04/05/06 | Pipeline, configuration-as-code, rolling release и откат образа. Автоматического обратного преобразования схемы БД не обещаем |
| CN.SEC.02 | Внутренний registry и proxy зависимостей, фиксированные версии/дижесты, сохранённые сборочные артефакты |
| CN.SEC.03/04 | Секрет-хранилище, разделение ролей, сервисных учёток и сетей; конкретные Kubernetes Secrets/namespaces отсутствуют — **эквивалентные меры требуют согласования** |

## Assumptions

Заданные в NFR-03 профиль сети и P75 уточняют неоднозначное обещание «до двух секунд» и требуют согласования маркетинга. Нагрузка 100 RPS — испытательная гипотеза, не вывод из требования CTO о 10 млн одновременных пользователей; при новых данных пересчитываются мощность и бюджет. Платёжные ограничения партнёров не обходятся нагрузочным тестом: для них нужны согласованные sandbox-квоты. NFR-08/09 зависят от подтверждённых площадок и копий; потеря площадки на 60 мин способна исчерпать месячный бюджет ошибок и не исключается из отчёта. Успешный стендовый тест не доказывает 30-дневный SLO.
