# Сценарии атрибутов качества

Каждый сценарий содержит шесть полей: источник, стимул, среда, артефакт, реакция, мера реакции. Значения ниже — проектные критерии приёмки, а не результаты уже проведённых испытаний. Идентификаторы связывают сценарии с [НФТ](nfr-registry.md).

## QAS-01. Отказ реплики приложения — NFR-01, 08, 12

| Поле | Содержание |
|---|---|
| Источник стимула | Среда исполнения / инженер испытаний |
| Стимул | Одна из двух реплик backend завершается во время запросов |
| Среда | Рабочая конфигурация одной страны, 100 RPS, БД и партнёры доступны |
| Артефакт | Входной балансировщик и реплики backend |
| Реакция | Неисправная реплика исключается из маршрутизации, другая обслуживает запросы; новая реплика запускается автоматически |
| Мера реакции | Исключение из трафика ≤30 с; RTO от отказа ≤60 с; за 15 мин испытания ≥99% корректных чтений и 0 утраченных подтверждённых заказов. Неуспехи входят в rolling SLO, а не объявляются исключением |

## QAS-02. Пиковая нагрузка и P99 — NFR-02, 04

| Поле | Содержание |
|---|---|
| Источник стимула | Покупатели, эмулированные генератором нагрузки |
| Стимул | 100 динамических RPS: 80 чтений, 15 команд заказа, 5 платёжных команд |
| Среда | 60 мин steady state после 10 мин прогрева, данные масштаба года 1; платёжный sandbox заменён согласованной заглушкой, без списаний |
| Артефакт | Backend, БД, кеш и фоновые процессы одной страны |
| Реакция | Система завершает операции без неограниченного накопления очередей; работает идемпотентность и ограничение ресурсов |
| Мера реакции | CAT-A ≥99,9%; ≥99% чтений ≤500 мс; ≥99% собственных платёжных команд ≤1 с; throughput ≥99% заданного RPS; backlog к концу ≤1 мин входного потока; ошибки не исключены из задержки. Итог не доказывает реальные квоты партнёров |

## QAS-03. Потеря основного узла БД — NFR-06, 08

| Поле | Содержание |
|---|---|
| Источник стимула | Отказ узла БД |
| Стимул | Основной узел теряется после подтверждения транзакций заказа и outbox |
| Среда | Основной узел и синхронная реплика в независимых локальных доменах; сохранён quorum для выбора primary |
| Артефакт | PostgreSQL, механизм выбора primary, подключения приложения |
| Реакция | Старый primary ограждается от записи, приложение переподключается к новому; при невозможности безопасного выбора запись прекращается |
| Мера реакции | RTO ≤5 мин от момента отказа, RPO=0 для подтверждённых commit в данном сценарии; 0 split-brain и повторных платёжных команд. 100% проверочных order/payment/outbox ID сверены после восстановления |

## QAS-04. Потеря всей площадки — NFR-09, 17

| Поле | Содержание |
|---|---|
| Источник стимула | Полное отключение дата-центра |
| Стимул | Приложение, primary и локальная реплика одновременно недоступны |
| Среда | Независимая зашифрованная копия и WAL до 5 минут давности доступны в разрешённой стране; целевая площадка и доступы подготовлены |
| Артефакт | Региональный контур заказов, платежей, копий и DNS/маршрутизации |
| Реакция | Дежурный с руководителем инцидента восстанавливают БД и приложение, проверяют данные и маршрутизацию; неизвестные платежи сверяются с партнёром до возобновления записи |
| Мера реакции | RTO ≤60 мин от отказа, RPO ≤5 мин; 0 передач PII в запрещённую юрисдикцию. При недоступной сверке чтение можно восстановить, но запись платежей остаётся закрыта и RTO платёжного пути считается нарушенным |

## QAS-05. Недоступный платёжный партнёр — NFR-05, 11

| Поле | Содержание |
|---|---|
| Источник стимула | API M-Pesa или Flutterwave |
| Стимул | На 15 минут все вызовы завершаются тайм-аутом или 5xx |
| Среда | Нагрузка NFR-04; собственная БД исправна; другой платёжный канал не предполагается автоматически эквивалентным |
| Артефакт | Платёжный адаптер, outbox и отдельный пул ресурсов |
| Реакция | Circuit Breaker прекращает бесполезные вызовы; Bulkhead изолирует ресурсы; пользователь видит pending/недоступность, подтверждённый заказ сохраняется; повторы создающей операции только с тем же ключом и после проверки статуса |
| Мера реакции | Ответ собственного API ≤2 с; deadline PAY-E 8 с; 100% истёкших инициаций учтены как bad PAY-E; CAT-A ≥99,9% за прогон; 0 дублирующих списаний; неизвестные платежи >15 мин попадают на ручную проверку |

## QAS-06. Перерыв доставки уведомлений — NFR-07, 11

| Поле | Содержание |
|---|---|
| Источник стимула | SMS-провайдер |
| Стимул | Отказ приёма сообщений в течение 30 минут |
| Среда | Новые обязательства поступают со скоростью 2/с; после восстановления договорная квота ≥10 сообщений/с |
| Артефакт | Outbox, worker уведомлений и журнал исходов |
| Реакция | Задания остаются устойчивыми; Retry с backoff/jitter не перегружает партнёра; после восстановления очередь разбирается с ограничением квоты |
| Мера реакции | 0 потерянных обязательств; все опоздания >5 мин учтены как bad NOT-H; после восстановления backlog очищен ≤15 мин при непрерывных новых поступлениях; каталог и заказ продолжают обслуживаться |

## QAS-07. Изменение цены и последняя единица — NFR-06, 10

| Поле | Содержание |
|---|---|
| Источник стимула | Продавец и два покупателя |
| Стимул | Цена обновляется, два покупателя одновременно оформляют последний экземпляр с устаревшей карточки |
| Среда | Две реплики приложения; в одной пропущено событие инвалидации |
| Артефакт | Кеш карточки, модуль заказов и таблицы остатков |
| Реакция | Кеш очищается по событию/TTL; checkout читает актуальные цену и остаток транзакционно; изменившаяся цена требует повторного подтверждения покупателем |
| Мера реакции | Публичная карточка обновляется ≤60 с; ровно один успешный резерв последней единицы; 0 списаний по неподтверждённой новой цене и 0 отрицательных остатков |

## QAS-08. Откат и перенос — NFR-13, 14

| Поле | Содержание |
|---|---|
| Источник стимула | Команда эксплуатации |
| Стимул | Новый образ не проходит smoke-проверку; затем требуется запуск предыдущего образа на втором типе compute |
| Среда | CI/CD, доступы и IaC готовы; миграция схемы совместима с двумя версиями приложения; только синтетические данные |
| Артефакт | Образ приложения, pipeline, конфигурация и резервная копия тестовой БД |
| Реакция | Pipeline возвращает предыдущий образ; перенос меняет инфраструктурные адаптеры и секреты, но не бизнес-код |
| Мера реакции | Откат ≤10 мин; 0 потерянных подтверждённых операций; развёртывание на втором типе compute ≤1 рабочего дня после доступа; все smoke-сценарии заказа/оплаты пройдены |

## Assumptions

QAS-03 не распространяет RPO=0 на потерю всей страны или повреждение всех копий. QAS-04 — условная приёмочная цель: размещение, стоимость и пригодность независимой копии должны быть подтверждены заданием 4. Если условие не выполнено, сценарий не принят. Основания сценариев — источники соответствующих NFR; QAS-06 предполагает согласованную квоту, а не обещает её наличие. При изменении профиля спроса сценарии и оценки TCO пересматриваются вместе.
