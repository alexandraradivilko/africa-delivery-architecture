# ADR-002: Публичный каталог кешируется с ограниченной свежестью, транзакционные данные проверяются в БД

**Дата:** август 2026 года, проектирование MVP.  
**Статус:** Предложено.  
**Владельцы:** CTO и разработчик каталога.  
**Шаблон:** ADR курса.

## Контекст

Мобильному покупателю нужен быстрый первый экран на нестабильной сети, а качественные фотографии увеличивают объём передачи: источник — артефакт 2, «Target audience» и «Experience requirements». При бюджете $5000/мес. нельзя добавлять отдельную инфраструктуру без доказанного эффекта: источник — артефакт 6, п. 1–2. Кеш должен уменьшить повторные чтения, сохранив корректные цены и остатки при оформлении заказа.

| Альтернатива | Преимущества | Ограничения / решение |
|---|---|---|
| Только БД, без прикладного кеша | Простая актуальность, меньше состояний | Больше повторных чтений; допустима как исходная контрольная конфигурация нагрузочного теста, но не основная для публичного каталога |
| CDN для публичных объектов + небольшой локальный кеш каталога | Нет отдельного cache-кластера, дешёвое масштабирование чтений | Кеши реплик расходятся; нужны TTL и доставка инвалидаций. **Выбрано** |
| Redis как общий кеш | Общая точка инвалидации, удобные структуры | Дополнительная зависимость, стоимость и отказоустойчивость; не решает автоматически актуальность. Отложено до измерений |

## Решение

| Данные | Где / ключ | TTL | Инвалидация и ограничения |
|---|---|---|---|
| Публичные проверенные фото товаров | CDN + браузер; ключ — hash содержимого, размер и формат | 1 год для immutable-версии | Изменение создаёт новый URL; старая версия перестаёт выдаваться каталогом. Удаление/жалоба — отдельный purge у CDN и исходного хранилища; подтверждение удаления контролируется оператором. Персональные фото/видео сюда не допускаются |
| Список, карточка и простой поиск | In-process LRU каждой реплики; ключ включает страну, язык, валюту, версию схемы, нормализованные фильтры/страницу | 30 с, jitter ±20%; общий возраст выдаваемых данных никогда >60 с | Cache-Aside. Изменение товара и событие инвалидации записываются транзакционно; каждая реплика читает журнал изменений раз в 5 с и удаляет карточку/связанные списки. Пропуск компенсирует TTL |
| Не найденный товар | Тот же локальный кеш, только публичное чтение | 5 с | Создание/публикация товара инвалидирует negative-cache |
| Статические файлы приложения | CDN, браузер, service worker; hash версии | 1 год для hash-ресурсов; HTML — `no-cache` с revalidation | Новый manifest переключает версию; старый кеш удаляется после активации. Offline показывает ранее загруженный публичный контент с явной отметкой |
| Корзина, профиль, заказ, статус оплаты, персональные ответы | Авторитетное состояние на сервере; общий кеш отсутствует | `Cache-Control: no-store` | CDN/service worker не сохраняют; повтор запроса идёт с проверкой прав. Локальный idempotency-key не содержит PII |
| Цена и доступный остаток при оформлении | Основная БД соответствующей страны | Не кешируются для принятия решения | Транзакционная проверка цены/резерва; при изменении цены покупатель подтверждает её заново. Отсутствие БД блокирует checkout, а не переключает его на кеш |

Локальный кеш ограничен **128 МБ на реплику** и LRU-вытеснением; это предел, а не обязанность занять весь объём. Нет пользовательских идентификаторов в ключах публичного кеша. Браузер не кеширует JSON каталога в этой версии: `no-store`, чтобы не складывать серверный TTL с неизвестным возрастом клиентской копии. Глобальный CDN хранит только классифицированные публичные объекты, не JSON/PII.

При cache miss только один запрос на ключ наполняет кеш (`singleflight`), остальные ждут в пределах deadline; число одновременных наполнений ограничено отдельным семафором. Истечение TTL распределяется jitter. Для чтений каталога при временной ошибке БД можно выдать последнюю корректную запись **не старше 60 с от исходного чтения**; возврат stale не продлевает её возраст. При отсутствии такой записи — явная ошибка, учтённая CAT-A.

Инвалидации читаются каждой репликой с собственным watermark; новый процесс стартует с пустым кешем. Журнал сохраняется 24 часа; если watermark отстал дальше сохранённого диапазона, кеш целиком очищается. Удаление товара из продажи проверяется авторитетно в checkout. Для срочного скрытия модератор запускает очистку кешей и блокировку выдачи SKU: задача не считается выполненной до подтверждения всех активных реплик; не подтвердившая реплика исключается из трафика. При недоступном механизме проверки скрытия сомнительная карточка не выдаётся из stale-кеша. CDN-purge изображения — отдельная зависимость: нельзя обещать его мгновенное исчезновение со всех клиентских устройств.

**Контроль:** hit/miss, возраст выдачи, число инвалидаций и watermark lag, объём LRU, concurrent fills, latency БД; нельзя использовать hit rate как доказательство корректности. QAS-07 проверяет пропуск инвалидации и гонку за последнюю единицу. Кеш не применяется к авторизации и финансовому аудиту.

## Последствия

**Положительные:** меньше повторных чтений и сетевого объёма, нет обязательного Redis-кластера. Работа укладывается в существующие compute/CDN-конверты TCO, если испытания подтвердят мощность.

**Отрицательные:** до 60 с устаревания публичной карточки, расход памяти на каждую реплику, дополнительная логика инвалидации. Новая реплика имеет холодный кеш. Заказ может потребовать повторного подтверждения цены, показанной ранее.

**Риски и пересмотр:** если при 100 RPS после оптимизации NFR-02 нарушается из-за БД либо кеш существенно ограничивает память, сравнить индексы/реплики БД и общий кеш по измеренной стоимости. Redis вводится отдельным решением с бюджетом, политикой вытеснения и проверкой деградации. Рост hit rate не оправдывает кеширование подтверждения платежа.

## Допущения и условия принятия

Большая часть чтений — публичные данные; разрешённый срок их устаревания 60 с должен подтвердить CEO. Фотографии предварительно классифицированы как публичные без персональных сведений. Технический механизм срочного скрытия и лимит CDN-purge проверяются до приёмки; при невыполнении теста функция модерации не считается готовой. Источник требований целостности — артефакт 1, покупки и выплаты; локализации — артефакт 3, «Nigeria».
