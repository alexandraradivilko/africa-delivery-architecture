# Data Residency Map

**Статус:** проект для MVP; владельцы — архитектор, CTO и ответственный за защиту данных (DPO). Контролёр данных — Africa Delivery; роли процессоров и самостоятельных контролёров уточняются в договорах. Персональными считаются также связанные идентификаторы заказа, платёжные токены, IP, журналы доступа и псевдонимизированные записи, если связь с человеком восстанавливается.

## 1. Что известно и что принято как ограничение

| Страна | Установлено источниками | Не установлено для проекта | Консервативное решение |
|---|---|---|---|
| Нигерия | Письмо требует локального хранения и ограничивает передачу; записка инвестора требует данных внутри страны. NDPC описывает условия передачи по ст. 41–43 NDPA, а не безусловный запрет любой передачи | Точные категории, отраслевые платёжные правила, регистрация/аудит применительно к компании, основания каждого потока | Все персональные и связанные операционные данные остаются в Нигерии; зарубежная поддержка и партнёры закрыты до разрешения конкретного потока |
| Кения | Письмо выделяет платёжные данные и регистрационные требования. DPA регулирует зарубежную передачу; локализация отдельных видов обработки требует отдельной проверки | Относится ли наш marketplace к специальным категориям локализации, какие условия применимы к платёжным метаданным и M-Pesa | Все персональные данные локальны, включая платёжные ссылки и копии; кенийский контур не размещается в ЮАР только потому, что это тот же континент |
| ЮАР | Письмо требует доказуемого управления согласиями. POPIA ст. 69 регулирует электронный direct marketing, ст. 72 — передачу за рубеж | Основание каждого вида обработки, применимые исключения для существующих клиентов, специальные категории, сроки | Будущий контур в ЮАР; маркетинг только по подтверждённому opt-in. Зарубежная обработка не включается без проверки |

Источники кейса — артефакт 3, три страновых раздела; артефакт 7, строка о локализации. Внешняя проверка: [NDPC, FAQ, cross-border transfers](https://ndpc.gov.ng/faqs/), [Kenya DPA 2019, ст. 48–50](https://new.kenyalaw.org/akn/ke/act/2019/24/eng@2022-12-31), [POPIA, ст. 69 и 72](https://www.justice.gov.za/legislation/acts/2013-004.pdf). Эти нормы не заменяют заключения по конкретным данным и партнёрам. Общий законодательный запрет вывоза всех данных каждой из трёх стран здесь **не утверждается**: более строгое размещение — временная политика проекта.

## 2. Обозначения мест размещения и оснований

- **NG:** Layer3 Cloud, Нигерия: основной compute в Лагосе, независимые копии/резерв в Абудже — запрашиваемая конфигурация, пока не подтверждённая для всех услуг.
- **KE:** локальный IaaS, кандидат Angani; основной и резервный ЦОД внутри Кении. Конкретные адреса и независимость должны быть в договоре; наличие офиса в Найроби не доказывает размещение compute.
- **ZA:** AWS `af-south-1`, Кейптаун; только будущий запуск ЮАР. Независимый DR в ЮАР выбирается отдельно до этого запуска; иностранный AWS-регион не используется по умолчанию.
- **B1:** исполнение заказа/договора — предлагаемое основание для необходимых операций; **B2:** отдельное согласие на канал и цель маркетинга; **B3:** конкретная юридическая обязанность, которую должен назвать юрист; **B4:** безопасность/защита требований — основание и срок требуют проверки соразмерности. Ни B1, ни B2 сами по себе не разрешают трансграничную передачу.

## 3. Карта категорий

Запись «NG / KE / ZA соответственно» означает три физически раздельных хранилища. Это не общая база с фильтром `country_id`.

| Категория данных | Страна субъекта | Где хранится / провайдер | Где обрабатывается | Основание и статус | Техническая мера / действие при передаче |
|---|---|---|---|---|---|
| Профиль, телефон, email, учётные данные, адреса | NG | NG, локальная PostgreSQL | Только NG backend и локальная поддержка | B1; локализация по кейсу | TLS, шифрование, собственная авторизация; внешний IAM не получает профиль; экспорт закрыт |
| Те же данные | KE | KE, локальная PostgreSQL | Только KE | B1; локальность — временное ограничение | Отдельные DB/секреты/домен; перевод в ЮАР только по процедуре T-01 |
| Те же данные | ZA | ZA, PostgreSQL в af-south-1 | Только ZA, после запуска страны | B1; проверка POPIA | Региональные роли и ключи; данные не реплицируются в NG/KE |
| Заказ, состав покупки, остаток с резервом, адрес доставки, возврат | NG / KE / ZA | NG / KE / ZA соответственно | Backend/worker страны; проверенный местный логистический партнёр | B1; минимальный набор адресных данных | Outbox локален; партнёру только требуемые поля, адрес обработки подтверждён; T-01 для иностранного получателя |
| Платёжная ссылка, токен, сумма, статус, выплата продавцу и сверка | NG / KE / ZA | В соответствующей стране, отдельные роли в БД | Местный адаптер и лицензированный партнёр с проверенными потоками | B1 + B3 после уточнения; договор обязателен | PAN/CVV/PIN не собираются платформой; hosted payment не освобождает от проверки страны обработки партнёра |
| Продавец: контакты, банковские сведения, KYC-документы | NG / KE / ZA | В своей стране; закрытое объектное хранилище для необходимого минимума | Авторизованные сотрудники и проверенный KYC/платёжный партнёр | B1/B3, состав ещё проверяется | По возможности KYC у партнёра, нам результат/ссылка; маскирование оператору, запрет публичных URL |
| Согласия, версии уведомлений, отзыв, suppression list | NG / KE / ZA | Локальные БД каждой страны | Модуль согласий и worker той же страны | B2 для маркетинга; доказательства — проверяемый срок | Цель + канал + время + версия текста + источник; повторная проверка согласия непосредственно перед отправкой |
| Outbox, DLQ и payload уведомления | NG / KE / ZA | Локальные БД каждой страны | Worker; проверенный SMS/WhatsApp-партнёр | B1 для необходимых уведомлений; B2 для рекламы | Не смешивать цели; неизвестная страна subprocessors блокирует канал. Доступный сайт не зависит от WhatsApp |
| Сырые логи, трассы, RUM, аудит, идентификаторы исходов SLI | NG / KE / ZA | Локальный стек каждой страны | Локально, включая support tooling | B4; сроки в ADR-003 | Allowlist полей, отсутствие payload/PII в общих логах; зарубежный SaaS и выгрузка raw отключены |
| Копии, WAL, snapshots, временные экспорты, ключи восстановления | NG / KE / ZA | В той же стране, отдельная площадка и учётная запись | Только разрешённые restore-стенды страны | То же основание, что у исходной категории | Шифрование не меняет местонахождение; проверка региона назначения, учёт удалений после restore |
| Обезличенные агрегаты для руководства | Все | До проверки — локально; после неё возможен общий отчёт | Локальная агрегация, затем разрешённый получатель | Обезличивание должно быть доказано | Нет order/user ID; исключение малых групп, порог ≥20 — лишь проектная мера, не доказательство анонимности; T-01 при остаточной идентифицируемости |
| Публичный каталог и очищенные фото товаров | Все | Локальный origin; разрешённая публикация через CDN | Публичный CDN; персональные API его обходят | Права на публикацию подтверждены | Удалены EXIF/контакты/лица; см. ADR-002. IP и логи CDN отдельно проверяются как потенциально персональные; иначе локальная раздача |
| Купленная база 410 тыс. номеров | Неизвестна/смешанная | В платформу не импортируется | Обработка/рассылка в проекте запрещена до доказательств | Основание не доказано | Не отправлять даже «запрос согласия» всей базе; текущую копию у маркетинга инвентаризировать, ограничить доступ и передать юристу решение об удалении/сохранении доказательств |
| Тестовые данные и сборки | Все | Код/образы без секретов могут быть общими | CI и тестовые стенды | Реальных субъектов нет | Генерация синтетики; production dump, телефоны и секреты в CI запрещены |

Страна определяется при регистрации и проверке обслуживания, а не только GeoIP, гражданством или кодом телефона. Неясная юрисдикция и межстрановая корзина не маршрутизируются автоматически: оформление приостанавливается до разрешения. Для MVP доступны покупки и продавцы внутри выбранной страны; переезд пользователя — контролируемая миграция, не копирование профиля по всему миру.

## 4. T-01: разрешение трансграничного потока

1. Владелец описывает цель, поля, субъектов, получателя, все страны обработки/копий/поддержки, subprocessors и дальнейшие передачи. Шифрованная копия и удалённый просмотр считаются потенциальной передачей, а не исключением.
2. DPO/юрист определяет основание обработки и отдельный механизм передачи; проверяет договор, отраслевые ограничения, необходимость оценки рисков и регистрации. Для NG дополнительно проверяется соответствие более строгому условию инвестора.
3. CTO реализует минимизацию, egress allowlist, региональные ключи, ограничение доступа и аудит; проверяет отрицательным тестом запрет неразрешённого адресата. Одна геоблокировка не является достаточным контролем.
4. Разрешение содержит страну, получателя, поля, срок действия и ответственных; версия policy применяется только к этому потоку. CEO принимает коммерческий риск, но не отменяет юридический запрет.
5. До письменного разрешения — синтетика, отключённый feature flag и запрет egress. При изменении subprocessors или цели разрешение пересматривается. В аварии T-01 не обходится.

## 5. Согласия и неопределённые вопросы

Механизм согласий реализуется во всех трёх контурах: отдельные необязательные opt-in на SMS/WhatsApp-рекламу, отсутствие предустановленного согласия, доказуемая версия текста, доступный отзыв. Отзыв блокирует новые отправки немедленно после commit и отменяет ещё не переданные маркетинговые задачи; уже переданное сообщение не обещается отозвать. Транзакционный статус заказа доступен без рекламного согласия. Источник — артефакт 3, South Africa; конфликт с базой — артефакт 2.

До реальных данных юрист подтверждает: классификацию платёжных/KYC-данных, регистрации и DPO, сроки по категориям, разрешённые адреса партнёров и поддержки, обязательные уведомления об инцидентах, условия публикации каталога/CDN. На ожидание полного заключения 4–6 недель не откладываются инвентаризация и разработка: разрешения для критического пути запрашиваются отдельно, как в Q-04. Неустановленный срок хранения не заменяется бессрочным хранением.
